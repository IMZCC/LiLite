# 轻哩 iOS 性能实测 · 2026-11-21

测试对象是本机工作区构建的 arm64 Release。基线保留了排查开始时工作区已有的修改。基线所在的 Git 提交是 `f6c4686`。页面测试使用正式导航、数据加载和播放入口，另用固定素材隔离图库与封面接收的开销。

## 帧率目标与测量方法

iPhone 18 Pro 模拟器运行 iOS 27.0。应用的刷新率设置、主屏的 `maximumFramesPerSecond` 和独立采样器均读到 60 Hz。应用已配置 `CADisableMinimumFrameDurationOnPhone`，并可在支持的屏幕上请求最高刷新率。120 Hz 的帧预算是 8.33 ms，当前模拟器的预算是 16.67 ms。未连接可用于验收的 ProMotion 真机。

在测试进程的主线程公共运行循环上附加 `CADisplayLink`，按时间戳统计相邻回调间隔。采样器只注入实验进程。表中 P95 表示 95% 的回调间隔小于或等于该值。滚动窗口从输入手势开始，包含减速，分位数也会包含这段时间中的空闲帧。该方法可定位主线程失约，但无法证明每次回调都有新画面呈现。Instruments 的 Animation Hitches 模板拒绝在该模拟器上采集。另用 Time Profiler 采集了约 55 秒的调用栈。基线中 `ArtworkStore.decode` 有 2630 个后台线程样本，`ArchiveDescription.cachedDescription` 有 43 个主线程样本。这里的计数包含调用链，不能换算为单次打开耗时。影片、字幕和 GIF 均按各自时间轴呈现。

第一次成组实验中，修改版 GIF 有一次 1522.26 ms 的显示回调间隔，同轮静图的最大值是 39.36 ms。保留该异常样本，无法单凭主线程回调判定其成因。随后独占模拟器界面、关闭 UI 自动操作与剖析，再按相同步骤各测三轮。静图打开的最大间隔从 101.58、94.12、101.32 ms 降至 35.65、50.00、33.33 ms。动图播放期从 34.61、33.47、91.89 ms 降至三轮均为 16.67 ms。

XCTest 在没有采样器和离线测试数据的环境中启动五次 Release 进程。耗时为 2.338、2.309、2.304、2.316、2.328 秒，平均 2.319 秒。这组数据包含模拟器系统开销。

## 源码检查与修改

对主应用 628 个 Swift 文件筛查滚动容器、主线程读盘与图片解码、时钟、周期观察器、分页和取消。另核对应用入口、MediaKit 桥接、Wire 网关、ArchiveKit、颜色库和遥测入口。第三方二进制解码器、系统渲染器及远端服务未列入源码修改。

| 路径 | 观察与处理 |
| --- | --- |
| 首页、空间、列表共用的远程封面 | 基线剖析中封面读取函数是后台热点。响应改成由 URLSession 串行代理分块接收，验证状态、声明长度和实际字节上限，沿用原缓存、重定向和证书策略。滚动预取的 URL 计算与排队移到独立 actor，复用为其他 URL 的单元格会取消旧请求。 |
| 全屏图片、表情动图 | ImageIO 在每个文件的独立 actor 解码，主线程更新图层。动图按编码延时预解下一帧，页面失活或移除时停止动画任务。 |
| 离线缓存、合集和分集 | 旧列表同步打开原尺寸封面。改成按控件物理像素后台降采样，离屏取消。列表过滤复用同一结果，分集按稿件计数改为一次遍历。下载字节更新仅通知进度控件，分片进度用校验后的 HTTP 范围计算，避免每次回调读回磁盘收据。 |
| 视频详情、UP 主和动态 | 视频介绍的链接检测从主线程移到后台，并按完整介绍内容缓存。资料相同但提及目标变更时会正确更新。空间主页列表按需创建，投稿和动态列表复用日期格式器。 |
| 听视频、歌词、空降助手 | 播放时钟与队列分开发布，歌词只在活动行切换时刷新高亮。歌词下载解析离开主线程，空降规则按保存内容复用，避免周期性重复解码。 |
| 外链与嵌套播放器 | 从外链进入离线合集并播放时，播放器曾再次推入离线缓存列表。将外链绑定限制在接收它的导航栈，外链和“我的”两个入口均复测到实际分集、播放队列和播放器控件。 |
| 我的、设置搜索 | 隐藏的个人栏目取消自动刷新与分页，同一请求还有可见使用者时继续。设置搜索已匹配静态关键词时，跳过动态偏好值的读取与归一化。 |

## 功能回归

- 响应体测试覆盖恰好达到上限、已声明超限、无长度响应中途超限、非 200 状态、100 次取消和 200 个并发读取。
- 介绍文本覆盖普通稿件链接、时间跳转、提及替换和缓存命中。下载分片覆盖正确范围、错位范围、长度不符及最后一段。
- 个人栏目用可控延迟的本地接口验证共享请求、一个使用者取消、最后一个使用者取消、重新显示后刷新和分页去重。
- ArchiveKit 的 5 项本地测试均通过。Wire 默认运行 25 项，其中 4 项为显式启用的在线测试，默认跳过。启用在线读取后，25 项中 24 项通过，公开动态点赞名单接口返回服务端错误 `-352`。


## 页面与场景覆盖

[逐页采样明细与界面控件](performance-simulator-2026-11-21.tsv) 按设备、轮次和入口列出结果。前后版本的推荐内容由线上接口提供，不能将不同视频、图片缓存冷热、并行宿主负载产生的差异都归因于代码。固定素材的对照单独列在上表。

- iPhone 的三个主栏及首页六个频道均从导航栏实际切换。另测排行榜、每周必看、入站必刷、搜索输入与结果、番剧与剧集、课程目录、音频与音乐详情、赛事详情、直播目录、直播分区、直播搜索、关注直播和直播间。
- 视频使用有可播内容的 BV1xx411c7mD，覆盖介绍、热门评论、楼中楼、更多面板、听视频，以及 874 × 402 横屏下的控制层与拖动。UP 主空间覆盖投稿、主页与动态页签。另从公开接口取得实际存在的两条动态，验证文字和图片内容，以免将错误态的帧时间当作动态阅读性能。
- iPhone 设置从主题颜色到开源许可的 27 个一级入口均验证了目标页。iPad Pro 11 英寸模拟器在 834 × 1210 窗口检查多列首页和详情，在 1210 × 834 窗口通过 XCTest 点击设置侧栏的 11 个分类并核对右侧控件。iPad 这些记录用于布局和路由验证。
- 私信长会话、登录后的关注流、账号收藏及历史、真实排队下载，以及付费媒体的持续播放没有本轮实测数据。游客搜索返回验证页，指定专栏 CV 返回限流，指定公共话题不存在。对应行只代表现场显示的状态。未测量长时间运行的真机功耗、温升及 GPU 实际呈现时间。

| 赛事详情 | 一次复测得到 284.87 ms 的单个长间隔，该窗口 P99 为 16.67 ms。单报分位数会漏掉这次停顿。 |

同一进程始终保持前台时，切换动画前的物理内存从 221 MiB 升至两次返回后的 545.9 MiB、四次后的 883.1 MiB、六次后的约 1.2 GiB，最后再等 12 秒仍约 1.2 GiB。另一次四次进出的堆快照显示，返回后仍有四个 PlayerModel、四个 MPVPlayer 和四个 MPVRenderer。33 块纹理占用 391,864,320 字节，代表性 31.7 MiB 分配的调用栈指向 MPVRenderer.draw、mpv 图像渲染和 OpenGL 纹理分配。32 秒的首页 Time Profiler 复测也记录到后台 OpenGL 软件绘制。前台和后台采用不同的渲染路径，因此内存复测使用前台物理内存。

## 首页视频转场

首页推荐、热门和推荐首张大卡进入普通视频详情时，复用项目原有的 CardZoomTransition。覆盖只传给当前卡片的 NavigationLink。推荐链接指向直播间、番剧或 UP 主等页面时使用原有设置。15 个链接用例覆盖 BV、AV、分 P、时间、评论定位和非视频资源。

测试探针记录了 UIKit 选取的转场和自定义动画器的实际调用。原版本在推荐、热门和 UP 投稿入口均记录到系统缩放。改动后，推荐和首张大卡使用自定义打开与返回，热门使用自定义打开与交互式返回。短侧滑取消后仍在详情，再完整侧滑回到推荐。UP 投稿仍调用系统缩放。
