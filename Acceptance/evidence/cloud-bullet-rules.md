Upstream `pages/danmaku_block/{controller,view}.dart`, `models/user/danmaku_rule.dart` and the player header distinguish original UID input from a tapped message's existing CRC. Native Settings → 弹幕样式与过滤 → 账号屏蔽规则 reads the active main account's three rule lists, provides add, edit (keyword/regex), confirmed delete and refresh. A replacement saves the new rule before deleting the old id; both stay visible if that deletion fails. Mutations use the common CSRF form with the captured account. Cache writes are keyed by account and fenced against concurrent refresh or removal. A player tap can separately block an already-hashed sender on the account or on this device.

Renderer layout in inline, fullscreen and offline play applies account rules alongside local filters, reloading on account changes. As in the baseline, account keywords are case-sensitive and account regex are case-insensitive with optional surrounding slashes. The content contract checks known UID/CRC pairs, keyword case, regex wrappers and direct hash handling without writing to a real account.
