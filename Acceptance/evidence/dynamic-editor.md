# 动态编辑器、草稿和发布回执

基线 d9e9626f1a3f89cd9ca85e18f61aaba02634e12a。固定版本 lib/pages/common/publish/common_rich_text_pub_page.dart 有光标插入、富文本转表单、图片选择/裁剪，dynamics_create 与 dynamics_repost 的 onSave 则是空实现。iOS 新增本机图文草稿

- 正文使用同一套 UTF-16 区间处理新建、转发和编辑。@ 选择绑定 UID，表情、投票分别发送 type 9、4；实体内部被手动改写会退回一般文字。选择编辑已有投票后原位替换，打开已有预约时以服务返回的真实 SID 检索与更新。预约编辑本身与保存整条动态是两次独立的服务操作
- 草稿的元数据与图片在 Application Support/PiliMomentDrafts 下分开存放；分区为主账号 + 新建、原动态转发、资源类型与编号、编辑目标。JSON 原子替换，保存和删除前核对上次读取的版本，跨窗口旧写入会报错。文字、富实体、光标、图片顺序、话题、预约、定时、评论范围均能恢复。图片在相册选择之后转存本机，不依赖照片选择器临时授权；草稿目录不进设备备份
- 编辑已发布动态时保留未改动原图的实况视频地址，允许新图和原图混排、裁剪和删除。裁剪实况图前提示会转为静态图。恢复旧草稿及上传前、提交编辑前都与服务原稿比对；改评论设置前检查 interaction-status 的 can_modify。无权限时仍可保留原设置
- 定时只允许公开动态，至少六分钟后且不超过原版的七天日期窗口。图片上传和最终写入均验证主账号；发布失败保留草稿。新建、转发成功后显示服务回执编号、定时或可见范围，按原设置可继续检查公开可见性。转发支持原转发链的作者、正文实体，选择「同时评论」后单独报告评论结果，评论失败不会再次发布动态
- 收藏夹等资源经 DynamicShareResource 进入同一编辑器，scene=5、web_repost_src.revs_id 指定真实资源类型和编号；普通动态转发使用 scene=4 与 dyn_id_str。两种目标既不混发，也不共用草稿
- Native/Checks/DynamicDraftCheck.swift 在 WSL 使用真实文件系统模拟新建/转发/编辑、账号和目标隔离、版本冲突、图片缺失、实体编辑、两种转发载荷与时间边界；10 个编辑器 Swift 文件在当前 iOS SDK 与原生宏环境独立 typecheck 通过。没有向真实账号发送上传、投票、预约、评论或动态写请求。系统 PhotosPicker/输入法选区、真机裁剪手势与登录态服务回执留给整体联测

资源分享入口：UGC 使用 AV 编号、type 8，并可选择同时评论(type 1)或 @ 原作者。AU 歌曲和音频播放页用 AU 的服务编号与 type 256；听 UGC 时则用 AV 编号与 type 8。影视按当前集的 ep_id 作转发资源，另用该集 aid 作评论对象；由 season.type 映射 1→4097、2→4098、3→4101、4→4100、5/7→4099。固定 lib/pages/video/introduction/pgc/view.dart 第 90 行的 isPgc 限定了第 469 行转发所在 actionGrid，PUGV 课程没有这个入口；保留课程原有系统分享，不给课程或漫画伪造影视类型。详情页与关联编辑器合计 16 份 Swift 源文件在 iOS Release 参数环境中独立 typecheck 通过，未提交真实资源分享
