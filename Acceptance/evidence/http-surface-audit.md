# 从 HTTP 调用反查可疑缺口

Checks/http_surface.py 从固定提交提取 lib/http/api.dart 中启用的单字符串常量、找出 Dart 里的引用，再与业务 Swift 源文件里的路径字面量作交叉核对；刻意排除账号接口分类表、生成的 RPC 类型和测试数据。运行 python3 Checks/http_surface.py --output dist/http-surface.tsv 可重建带上游行号、调用文件和原生文件行号的明细

首轮共检出 311 个定义，其中 182 个有调用且能在原生源中找到同路径，108 个有调用、需要人工追踪，21 个未找到实际业务调用。这里的“同路径”不检验账号、方法、参数、UI 可达性和回包处理；“需要追踪”中也会包含字符串拼接、改用 gRPC、改用原生系统能力或服务升级换路径的场景。它与 655 项页面/偏好清单独立，不能当作已实现功能数或完成比例

这轮发现登录有具体差异：已有网页登录 Cookie、网页扫码及移动令牌绑定，但同机用户缺少官方交互登录入口，现已补上。移动端自动发令牌、动态预约/投票管理、直播间反馈和管理类动作等仍需沿着实际触发点继续核查。所有本地对照均不执行账号写操作


## 逐条回看

后续复核已把 311 个常量全部归入 [HTTP 审核矩阵](http-service-matrix.json)。最初“没有找到同路径”的条目有动态拼接、Web 替代移动端点、官方网页登录、上游无调用包装和受官方客户端授权约束的场景，不能都当作缺失。最初 51 个仍需核查的字面量差异中，确认并修复 UGC 合集面板订阅/取消的真实操作；修复后原始扫描为 240 命中、50 个还需看矩阵、21 个无常量引用（数字以当前源代码重新运行结果为准）。239 个只做字面量索引的条目不签用户行为。

[gRPC 方法矩阵](grpc-service-matrix.json) 另按 35 个可执行业务方法和 2 个未调用包装展开。[验证说明](service-protocol-review.md) 区分实际端点、等效服务、用户主动在官网完成的身份验证、无调用代码和服务器的权限前提。可用 python3 Checks/http_surface.py --reviewed-output dist/http-reviewed.tsv 导出可筛选的完整差异表；这个操作不会向网站发请求
