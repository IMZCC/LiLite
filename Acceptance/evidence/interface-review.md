复验入口（WSL，工作目录 `Native/`）：

- `bash Checks/interface_acceptance.sh`：运行纯 Swift 行为矩阵、ID/符号/文件、固定上游触发枚举、实际 Info.plist 和隔离构建标记。Native-only 源归档仍查原生行为与材料；有完整 Git 仓库时额外逐处对照固定版本的源文件
- `bash Checks/setting_search.sh`：实际控件与 314 个锚点一致，同时验证两个网络设置作用域和按当前值搜索
- `bash Checks/theme_colors.sh`：主题参考值与全部组合；`Checks/run.sh` 中的 `NavigationShellCheck`、`InteractionPolicyCheck`、`FeedColumnCheck` 分别验证导航规则、手势阈值/缩放、列数及最短列。备份/恢复的格式和安全边界另见 [backup-restore-audit.md](backup-restore-audit.md)
- iOS 定点编译：以 xtool 的 Release Swift 前端命令和对应的 iPhoneOS 27.1 SDK 模块图，使用同一棵树的 PiliWire（包括回复投票）和 PiliArchive 模块；以外观/导航/账号面板/触感调用的实际 SwiftUI 源作为 primary、全项目应用源作为依赖做 arm64 iOS 17 类型检查。全包 Release 仍由仓库的 `bash build.sh --release` 统一复验

`verified` 为纯行为或映射已有执行数据；`implemented` 为消费者和系统控件已接入并通过 SDK，实体 Taptic Engine、ProMotion、旋转/VoiceOver、剪贴板/文件挑选器、身份验证、账号云端写入等分别留给真机。`not-ios` 为固定原版仅放在桌面条件内的窗口标题栏和托盘图标。`platform-equivalent` 为 iOS 平台等效做法。`cross-domain` 只限夹带其他业务的首页和“设置相关”总括项，不把本域结论外推到所有服务
