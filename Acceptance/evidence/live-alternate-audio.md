# 直播 HLS 独立音轨、轮询与共同时间轴

- 在直播线路菜单中可选默认或指定解说音轨。系统 HLS 使用 AVMediaSelectionGroup 切换，兼容解码路径按 master 中同组 EXT-X-MEDIA 的名称、语言及 DEFAULT/AUTOSELECT 选择原音轨。重新取流时优先沿用同一选项，无法保持时给出提示，不以另一份解说静默替代
- 视频和外置音频各自读取有界清单、独立跟进各自的 MEDIA-SEQUENCE、初始化头、ByteRange、更新与终止。允许媒体 URL 的来源遵循已取得直播线路的同一组 HTTPS 主机；不预取未选音轨，不取任何加密密钥。双路共享设置的直播字节缓存预算
- 对 CMAF / MPEG-TS 解复用后的包保留真实 PTS/DTS 和时基。两条清单都给出 PROGRAM-DATE-TIME 时，按实际墙钟建立共同原点；没有节目日期时保留媒体时钟并处理 33 位 MPEG 时间戳回绕。AAC/MP3/AC-3/E-AC-3 的 packed audio 按 [RFC 8216 §3.4](https://www.rfc-editor.org/rfc/rfc8216#section-3.4) 检查每段 ID3 PRIV 的 90 kHz 时间戳，剥去元数据头后将原音频包交回 HLS；拒绝不一致的时间线，不以视频和音频清单具有相同编号为前提
- 两个有界、可取消的读取队列分别喂给 FFmpeg，只保留每轨一个等待排序的包。按共同 DTS 交错输出；MPEG-TS / ADTS AAC 仅变更容器封装。切换音轨、跨时间线、清晰度和线路重连建立新会话；不需要再向 B 站索要其他视频账号或权限。不含合法节目锚点/媒体时钟的异常外置清单、受保护的输入不尝试猜测解密
- 可重复验证：WSL 运行 python3 Checks/live_decode.py。英语 CMAF 与另一语种的 MPEG-TS 清单使用不同的编号并独立滚动；输出 66 个真实画面和所选音频包，分别核对每个原 AAC 包的哈希，验证另一声轨不同。设定两清单墙钟起点相差 -250 ms 时，验证丢弃直播头部已有的过早音包后仍保留预期偏移。两组断开后重新打开，从后面的窗口各输出 42 帧，并继续播放用户选中的原音频。无节目日期的四组 packed audio 分别输出原 AAC、MP3、AC-3、E-AC-3 包，基于 ID3 时钟实测偏移约 186.9 ms，目标为 187.5 ms
- MediaKit 的连续解复用核与视频核均用实际 SDK 编译为 iOS arm64；SwiftUI 选轨、双路读取、系统音轨切换入口通过独立设备 SDK 类型检查。主机测试使用合成素材与受控 URLSession 回调；设备扬声器/耳机、现场 CDN 清单、iOS 系统音轨选择和长时间网络切换留在整机验收
