# 话题详情和话题选择

比对固定版本的 `lib/pages/dynamics_topic`、`dynamics_select_topic`、`dynamics_topic_rcmd`，以及 `lib/http/{dynamics,fav,search}.dart` 和 `lib/utils/app_scheme.dart`

- 动态卡的话题、推荐目录、收藏话题、移动端/桌面分享链接，以及原版的 `bilibili://m.bilibili.com/topic-detail` 进入同一个原生详情。标题、描述、浏览和讨论数来自顶栏，发起人头像和名字可进入空间。分享使用原版的移动端链接；举报按原版进入带话题 ID、名称和当前主题的官方网页
- 列表采用服务给出的排序编号和名称，按返回偏移继续加载，保留动态详情卡的交互和瀑布流偏好。普通动态、折叠提示独立识别；点击折叠项在原位置替换后去重。网络失败保留重试，刷新或换排序令过期结果失效
- 推荐身份仅用于阅读顶栏和普通列表。折叠列表依上游 API 使用主账号角色。点赞与收藏只在操作时使用主账号 CSRF，主账号不同于推荐身份时先读主账号真实状态并确认，再决定发送添加还是取消。成功后同步按钮和计数
- 参与话题会以当前名称和 ID 预填原生动态编辑器。搜索话题的选择器支持空关键词、300ms 防抖和 20 条偏移翻页；游客推荐接口返回空数据时正常显示空列表

2026-11-12 以原版路由注释中的公开话题 `1028161` 无凭据只读核验：顶栏返回对应 ID 和发起人，普通及折叠结果各 20 张动态卡，服务排序为 2「热门」、3「最新」。Linux Swift 用工程内的 TopicPage、DynamicEntry、TopicHeader、SharedLink 实际解码，并检查折叠替换、唯一 ID 及包含中文和 & 的举报网址；两个网页链接及移动 Scheme 也加入现有 ContentContractCheck。话题选择服务的空关键词第一页返回 20 个话题，匿名推荐目录可返回 code=0、data=null

可在 Native 目录的 WSL Swift 环境执行 `python3 Checks/topic_readback.py` 复验公开响应。此检查依赖线上公开内容，不作为离线构建的必需步骤。没有向服务提交点赞、收藏、举报或发布；登录状态写入和 iPhone 操作体验留给最终验收
